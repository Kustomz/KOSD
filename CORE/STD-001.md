# STD-001

**Version:** 2.0.0 (Draft)
**Status:** Draft

## Purpose

Defines the standard metadata and structural requirements applied to KOS modules and governed KOSD files.

## Core Requirements

1. KOS module identity must be explicit.
2. Module version must be explicit.
3. Module status must be explicit.
4. Stable module IDs must be preserved.
5. Locked content must not be silently altered.
6. Changes must be traceable through the KOSD change/release process.
7. Missing information must not be silently invented.
8. A draft module is not authoritative until it passes the applicable validation/release process.

## Required Module Metadata

A KOS module should identify, as applicable:

- Module ID
- Module name
- Version
- Status
- Purpose
- Relationships/dependencies
- Change or resolution history

## Status Discipline

Status must distinguish draft material from validated/released material.

The existence of a file in KOSD does not by itself make the file authoritative.

## Recovery Relationship

When KOSD is built from Kustomz Project Recovery, recovery items provide project-state context. Recovery items marked REVIEW must not be silently promoted to authoritative KOSD content.

## Boundary

This draft records the Core standard direction required for the current KOSD build. It does not invent detailed field schemas or validation criteria that have not yet been established elsewhere in the project.
