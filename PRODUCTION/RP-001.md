# RP-001

**KOS Version:** 2.0.0 (Draft)
**Module Name:** CSR2 Legends Restoration Pricing Resolver
**Version:** 1.0
**Status:** LOCKED SPECIFICATION

## Purpose

Define the authoritative Toolbox process for deriving CSR2 Legends restoration requirements directly from the game's restoration-pricing data. The Toolbox must derive values dynamically for newly introduced Legends cars and must not hard-code individual car totals.

## Core Rule

**The Toolbox shall reproduce the game's restoration-pricing data path rather than maintain a manually curated restoration-cost table.**

Production resolution path:

`CSR2 game metadata → RestorationCarPricing.metadata → RestorationCarPricingDatabase → RestorationPricingManager → RPartsPrice records → applicable restoration-cost aggregation → Required to restore`

## Input

The resolver accepts a CSR2 game-version data set containing the restoration pricing metadata. It shall locate `RestorationCarPricing.metadata` or the version-equivalent source identified through the game's metadata/database configuration.

## Decode Requirements

CSR2 NMG metadata using the identified Alpha LZHAM path shall be decoded with an LZHAM Alpha8-compatible decoder.

For the validated format:
- NMG header: first 16 bytes
- decompressed-size field: bytes 12–15, little-endian
- compressed stream begins at byte 16
- validated restoration pricing stream uses the `0x0E` LZHAM path
- final 4 bytes are excluded from the compressed stream for the validated format
- Alpha8 zlib-compatible stream mode is required
- 15-bit LZHAM window is required

The implementation must detect/validate the format rather than blindly assuming offsets when a future game version changes the container.

## Parse Requirements

Parse the decoded `RestorationCarPricing.pricingList` and retain, at minimum:
- car DB key
- restoration asset identifier
- restoration type/level where represented
- `RPartsPrice`
- `RTimer`
- `GoldPrice`
- `PartSide`

## Automatic Car Discovery

The resolver shall discover cars from the pricing records themselves.

It shall group restoration records by base car DB key. Component identifiers such as `bod0`, `bod1`, `bod2`, `whe0`, `eng0`, `int0`, and `int1` are data-derived restoration identifiers and shall not require a hard-coded list of Legends cars.

A newly added Legends car must therefore be resolvable when its restoration pricing records appear in the new game's pricing database.

## Calculation

The resolver shall reproduce the game's applicable restoration-cost aggregation represented by `RestorationPricingManager.GetCostSumForRestorationLevel(...)` and related pricing methods.

The resolver shall:
1. identify the applicable restoration records for the car/setup/level;
2. extract their `RPartsPrice` values;
3. aggregate the applicable values;
4. expose the resulting restoration requirement as the Toolbox's `requiredRParts` value.

The implementation must not assume that every record in a car's pricing block is always applicable; applicability must follow the game's restoration-level semantics as those are established through continued reverse engineering.

## Reference Validation Case

Validated against `Ferrari_250GTOClassic_1962`:

- `bod0` = 1800
- `bod1` = 2200
- `bod2` = 2600
- `whe0` = 1000
- `eng0` = 2800
- `int0` = 2000
- `int1` = 2400

`1800 + 2200 + 2600 + 1000 + 2800 + 2000 + 2400 = 14800`

Expected resolver result:

`requiredRParts = 14800`

## Validation Requirements

Every implementation shall include a regression test using the Ferrari 250 GTO reference data.

Validation levels:

1. **Decode validation** — pricing metadata successfully decodes.
2. **Parse validation** — `RestorationCarPricing.pricingList` is recovered.
3. **Record validation** — expected Ferrari records and prices are present.
4. **Calculation validation** — resolver produces `14800`.
5. **Source validation** — resolver identifies `RestorationCarPricing` as the economic source, not the car's `RestorationManifest`.
6. **Version validation** — changed/missing schema, records, or calculation semantics cause a flagged result rather than silent publication.

## Output Contract

Normalized output shall contain:

```json
{
  "carDBKey": "Ferrari_250GTOClassic_1962",
  "requiredRParts": 14800,
  "pricingSource": "RestorationCarPricing",
  "components": [
    {"id": "bod0", "rParts": 1800},
    {"id": "bod1", "rParts": 2200},
    {"id": "bod2", "rParts": 2600},
    {"id": "whe0", "rParts": 1000},
    {"id": "eng0", "rParts": 2800},
    {"id": "int0", "rParts": 2000},
    {"id": "int1", "rParts": 2400}
  ]
}
```

## Non-Goals

- Do not hard-code restoration totals for individual cars.
- Do not use external/wiki restoration totals as the production source.
- Do not treat `Ferrari_250GTOClassic_1962_RestorationManifest` as the economic source.
- Do not substitute normal `CarPricing` upgrade prices for restoration prices.
- Do not silently accept an unvalidated future metadata format.

## Dependencies / Evidence

Authoritative research basis:
- `RESEARCH/CSR2/GAME_VERSIONS/6.7.0/ANALYSIS/RestorationPricing_Source.md`
- CSR2 IL2CPP metadata identifying `RestorationPricedAsset`, `RestorationPricingManager`, and `RestorationCarPricingDatabase`
- Decoded `RestorationCarPricing.metadata`
- Ferrari 250 GTO seven-record / 14,800 validation

## Implementation Boundary

RP-001 is the locked KOSD specification for the Toolbox capability. The production implementation may evolve as additional CSR2 versions are reverse-engineered, but it must preserve the core rule: **derive from the game's own restoration pricing data and calculation semantics.**
