# GOV-001

**KOS Version:** 2.0.0 (Draft)
**Status:** DRAFT / RECOVERY-MAPPED

## Purpose

Governance module for the Kustomz Operating System (KOSD).

## Source Boundary

This module is a recovery-derived governance map. It does not promote recovery items to authoritative status and does not invent missing governance definitions.

## Recovery-Derived Governance Principles

### Operational Approval Gates — E-009

KOS may automate discovery, acquisition, dependency handling, testing, comparison, and validation of tools.

A Kustomz approval gate is required before a newly discovered or replacement tool becomes the production tool.

Automation may prepare and validate a change, but production tool replacement remains subject to Kustomz approval.

Existing validated tool versions remain available for fallback, comparison, and reproducibility.

**Recovery status:** REVIEW. Not yet promoted.

### Evidence & Provenance — E-010

KOS preserves the distinction between raw evidence, decoded/derived information, reference/database values, and unresolved information.

Evidence classifications established in recovery:
- CONFIRMED
- STRONGLY CORRELATED
- DERIVED
- REFERENCE/DATABASE VALUE
- UNKNOWN / NOT RECOVERED

Actual game files are primary evidence for what they physically contain. Tool output is derived from source data and must retain provenance. Databases are reference sources unless independently established as authoritative for a specific claim. Mockups are not authoritative evidence.

Meaningful KOS results should retain sufficient source, game/version, asset/data source, toolchain, dependency, processing-path, validation-state, and classification information.

**Recovery status:** REVIEW. Not yet promoted.

### Master / Locked / Pause Handling — O-001/O-002/O-003

Recovery records the following as items requiring review:
- Master is authoritative; historical information does not become authoritative merely because it appears in old context.
- LOCKED means authoritative until explicitly changed, superseded, or unlocked.
- When a workstream is paused, record the exact stopping point, current state/hypothesis, active boundaries, and next intended target in Master.

**Recovery status:** REVIEW. Not yet promoted.
